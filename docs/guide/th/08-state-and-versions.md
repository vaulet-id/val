# State และเวอร์ชัน

```val
state {
  member:         LoyaltyMember?
  lifetimePoints: int default 0
}
```

เป็นของคุณ อยู่บนเครื่องผู้ใช้ เปลี่ยนได้โดย `update` ใน action เท่านั้น ใช้
`default` ไม่ใช่ `=` — ภาษานี้ไม่มีการกำหนดค่า

## มันถูกแฮช

หลังทุก action wallet สร้าง Merkle tree เหนือใบ `(path, value)` ของ state คุณ
แล้วบันทึกรากไว้ record ถัดไปพารากก่อนหน้าไปด้วย ทั้งสองจึงต่อกันเป็นห่วงโซ่

นี่คือการ**ทำให้การแก้ไขปรากฏ** ไม่ใช่การกันการแก้ไข state อยู่บนเครื่องของผู้ใช้
และเขาโยนทิ้งได้ — นี่ไม่ใช่บล็อกเชนและไม่มีใครอื่นถือสำเนา สิ่งที่ห่วงโซ่ให้คือ
การตรวจจับ สำหรับใครก็ตามที่เก็บ record ก่อนหน้าไว้

นั่นคือเหตุผลที่ผู้ตรวจสอบจำรากล่าสุดที่เห็นไว้ และเป็นเหตุผลที่ credential ที่
ออกไปบันทึกรากที่มันมา การย้อนกลับทิ้ง credential ที่ถูกเซ็นแล้วชี้ไปยัง state
ที่ไม่มีอยู่อีกต่อไป

## ทำให้มันเล็ก

**ไม่เก็บค่าที่คำนวณได้** ผลรวมที่คุณคำนวณจากสิ่งที่มีอยู่แล้วคือสำเนาที่สองของ
ตัวเลข หน้าจอมี `compute` ไว้เพื่อการนี้

**ไม่เก็บ state ของการโต้ตอบ** แท็บไหนเปิดอยู่เป็นของ wallet

ขนาดถูกจำกัดโดย wallet และขีดจำกัดถูกตรวจก่อน state จะ commit การรันที่จะเกินขีด
จึงไม่เปลี่ยนอะไรเลย

## การเปลี่ยนรูปร่างคือเวอร์ชันใหม่

**การเปลี่ยนรูปร่างของ `state` ทำให้ state ของเวอร์ชันนั้นเริ่มจากว่างเปล่า**
ไม่มี migration ไม่มี compatibility shim ไม่มี dual reader

หมายเหตุ: migration คือโค้ดที่รันกับข้อมูลที่เวอร์ชันปัจจุบันไม่เคยผลิต ไม่มีใคร
ใช้งานมันจริง และพิสูจน์จาก execution record ไม่ได้เพราะไม่มี action ไหนเป็นคนทำ

ผู้ใช้ถูกถามอีกครั้ง และสิ่งที่เขาถูกถามอ่านเข้าใจได้เพราะไม่มี state ที่สามที่
เป็นครึ่งหนึ่งของแต่ละอัน

**ดังนั้นอย่าเอาอะไรที่เสียไปไม่ได้ใส่ไว้ใน `state`** ถ้ามันสำคัญ มันควรอยู่ใน
credential ที่คุณออกให้ — ซึ่งผู้ใช้เก็บไว้ และรอดข้ามเวอร์ชันถัดไปของคุณ —
หรืออยู่บน backend ของคุณเอง
