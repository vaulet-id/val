# ทำไมต้องสร้างภาษาใหม่

คำถามแรกที่คนมีเหตุผลทุกคนถาม: ภาษามีให้เลือกเยอะแยะ แล้วทำไมต้องมีอีกภาษา

มีสามทางที่ง่ายกว่านี้ และแต่ละทางดีกว่า VAL อยู่อย่างละหนึ่งเรื่อง

## SDK ในภาษาที่คุณใช้อยู่แล้ว

ไม่ต้องเรียนอะไรใหม่ เอดิเตอร์ทุกตัวเข้าใจ และ ecosystem พร้อมอยู่แล้ว
สำหรับปัญหาส่วนใหญ่ นี่คือคำตอบที่ถูก

แต่มันเป็นคำตอบที่ผิดสำหรับเรื่องนี้ เพราะการเรียกฟังก์ชันมองไม่เห็นจนกว่ามันจะทำงาน
wallet จึงบอกไม่ได้ว่าแอปจะขออะไรก่อนที่มันจะขอ ผู้ใช้ก็เลยไม่ถูกบอกด้วย —
และหน้าจอที่ขอความยินยอมจากเขา กลายเป็นสิ่งที่แอปผู้ขอเป็นคนเขียนเอง

ส่วนคำประกาศนั้นอ่านได้ก่อนที่อะไรจะเกิดขึ้น เทียบความต่างกับเวอร์ชันที่เคยเชื่อไปแล้วได้
ให้ผู้เผยแพร่ลงนามได้ และปฏิเสธได้

## webview กับ bridge

เร็วที่สุดในการเริ่มใช้ เพราะทีมมีเว็บแอปอยู่แล้ว เอาไปใส่ในเฟรม
แล้วต่อฟังก์ชันไว้ข้าง ๆ ไม่กี่ตัวก็จบ

แต่ wallet ไม่ได้เป็นคน compile โค้ดนั้น และไม่ได้เป็นคนวาดพิกเซลเหล่านั้น
มันจึงยืนยันไม่ได้ว่าอะไรทำงานไป และยืนยันไม่ได้ว่าผู้ใช้เห็นอะไร
ทุก capability ที่ความปลอดภัยตั้งอยู่บนสองข้อนั้น — การออก credential
การรับชำระเงิน การลงนามในสิ่งที่แอปเป็นคนประกอบขึ้นมา — จึงให้ไม่ได้

## manifest บวกโค้ดอะไรก็ได้

ประกาศ capability ไว้ล่วงหน้า แล้วเขียนตรรกะด้วยอะไรก็ได้ตามใจ
แบบนี้ได้ความปลอดภัยมาเกือบหมด และเป็นการออกแบบที่ใช้ได้จริง —
แอปแบบ webview บนโฮสต์อย่าง Vaulet ก็คือแบบนี้

สิ่งที่ไม่ได้มาคือการตัดสินใจที่ใครก็ตรวจซ้ำได้ คำถามว่า *ทำไมถึงอนุมัติ*
มีคำตอบก็ต่อเมื่อตรรกะวิเคราะห์ได้และการทำงานเป็น deterministic —
ส่วน "โค้ดอะไรก็ได้" คือส่วนที่ไม่เป็นทั้งสองอย่างพอดี

## ทำไมไม่ใช้ TypeScript แบบจำกัดเอา

นี่คือรูปที่แข็งแรงที่สุดของข้อโต้แย้ง และควรตอบให้ดี — เอาภาษาที่ทุกคนรู้จัก
ห้ามส่วนที่อันตราย แล้วแจก linter ไปหนึ่งตัว

**การจำกัดคือคำสัญญาที่รักษาไม่ได้** อะไรที่ไม่ได้ถูกห้ามไว้อย่างชัดเจนก็ยังไปถึงได้
และเครื่องมือรอบภาษานั้น — เอดิเตอร์ ตัวตรวจชนิดข้อมูล ตัวจัดการแพ็กเกจ
และ dependency อีกพันตัวที่ตามมา — ไม่รู้จักกฎของคุณ และไม่ได้ถูกสร้างมาเพื่อบังคับใช้มัน
การเขียนว่า "บล็อกนี้ห้ามมี effect" ในภาษาที่ effect อยู่ทุกที่
คือการรีวิวโค้ด ไม่ใช่คอมไพเลอร์

และส่วนที่ทำให้ VAL คุ้มที่จะมี ไม่ใช่ส่วนที่เกิดจากการตัดออก:

- `Verified<T>` ต้องเป็นชนิดข้อมูลที่ตัวตรวจบังคับใช้จริง ซึ่งแปลว่าต้องเป็นเจ้าของ
  ตัวตรวจอยู่ดี
- determinism แปลว่าไม่มีนาฬิกา ไม่มีการสุ่ม ไม่มีทศนิยม และแตะเน็ตเวิร์กไม่ได้เลย
  ถึงตรงนั้นสิ่งที่เหลือก็เป็นภาษาคนละภาษาที่ใส่เสื้อ TypeScript อยู่ —
  โดยที่ยังต้องตรวจสอบพื้นที่ทั้งหมดของ TypeScript อยู่ดี
- wallet เป็นคนวาดหน้าจอ หน้าตาของแอปจึงเป็น component tree อิสระตั้งแต่แรกไม่ได้

สิ่งที่รอดจากทั้งหมดนั้นเล็กพอที่จะเขียนเป็นข้อกำหนดได้ในเอกสารเดียว
เรื่องนี้สำคัญกว่าที่ฟังดู — ข้อกำหนดคือสิ่งที่คนอ่านตอนกำลังตัดสินใจว่า
จะเชื่อแอปที่เขียนด้วยภาษานี้ได้ไหม

## เมื่อไหร่ที่ VAL คือคำตอบที่ผิด

ถ้าแอปต้องการการคำนวณอิสระ หน้าตาที่ออกแบบเอง หรือ ecosystem ของไลบรารี
VAL จะขวางทุกก้าว — แอปแบบนั้นควรเป็นแอปธรรมดาที่ขอหลักฐานจาก wallet
ผ่าน OpenID4VP แทน

VAL มีไว้สำหรับของเล็ก ๆ ที่มีรูปร่างแบบ credential
ซึ่งวันหนึ่งจะมีคนต้องอธิบายผลลัพธ์ของมัน — credential ใบไหน นโยบายข้อไหน
กฎข้อไหน และการทำงานครั้งไหน
