# สิ่งที่คุณกำลังสร้าง

Micro App ทำงานอยู่ใน wallet ของใครสักคน ข้างๆ พาสปอร์ตและ credential
ธนาคารของเขา นั่นคือเหตุผลทั้งหมดที่ภาษานี้มีรูปร่างอย่างที่เห็น

คุณไม่ได้กำลังส่งมอบโปรแกรมที่รันบนเซิร์ฟเวอร์ของคุณเอง คุณกำลังขอให้คนแปลกหน้า
ยอมให้โค้ดของคุณไปนั่งอยู่ข้างสิ่งที่อ่อนไหวที่สุดที่เขามี — และคำตอบของคำถาม
"แล้วทำไมฉันต้องยอม" จะเป็น "เชื่อเราสิ" ไม่ได้ แพลตฟอร์มนี้จึงถูกสร้างมาเพื่อให้
เขาไม่ต้องเชื่อ: สิ่งที่แอปของคุณทำได้ถูกอนุมานจากโค้ดของคุณและแสดงให้เขาเห็น
ก่อนติดตั้ง ส่วนสิ่งที่มันทำไปแล้วถูกบันทึกในรูปแบบที่เขาส่งต่อให้คนอื่นดูได้

นั่นมีราคาที่คุณต้องจ่าย และควรรู้ว่าจ่ายอะไรบ้างก่อนเริ่ม

## สิ่งที่คุณได้

**คุณไม่ต้องสร้างระบบ login เลย** ตัวบุคคลถูกระบุตัวตนไว้แล้ว ด้วย credential
ที่ออกโดยผู้ที่มีน้ำหนัก — รัฐ ธนาคาร โบรกเกอร์ที่มีใบอนุญาต หรือนายจ้าง
คุณขอ claim แล้วคุณก็ได้ claim ที่ตรวจแล้ว

**คุณไม่ต้องเก็บข้อมูลของเขา** ข้อมูลอยู่ใน wallet ของเขา คุณอ่านมันภายใต้
policy ที่คุณระบุชื่อไว้ ใช้งาน แล้วมันก็ไม่ได้กลายเป็นแถวหนึ่งในฐานข้อมูลของคุณ
ที่คุณต้องรับผิดชอบต่อไป

**คุณพิสูจน์บางอย่างได้โดยไม่ต้องเห็นมัน** "คนนี้อายุเกินยี่สิบ" เป็นคำถามที่
ได้คำตอบโดยไม่ต้องรู้วันเกิด ระบบส่วนใหญ่ทำแบบนี้ไม่ได้ และระบบส่วนใหญ่ก็ขอ
วันเกิด

**สิ่งที่คุณทำพิสูจน์ได้** action หนึ่งครั้งสร้าง record ที่ถูกเซ็น: โค้ดชุดนี้
เวอร์ชันนี้ state ก่อนหน้านี้ state หลังจากนี้ เมื่อลูกค้าโต้แย้งธุรกรรม
นั่นคือสิ่งที่คุณมี แทนที่จะเป็น log file ที่คุณเขียนเอง

## สิ่งที่คุณต้องยอมเสีย

**คุณไม่ได้วาดหน้าจอ** host เป็นคนวาด คุณประกาศ `card` `row` `button`
แล้ว host ตัดสินว่าสิ่งเหล่านั้นหน้าตาเป็นอย่างไร ทุกแอปบนแพลตฟอร์มจึงดูเหมือน
เป็นส่วนหนึ่งของแพลตฟอร์ม ซึ่งเป็นข้อดีสำหรับผู้ใช้และเป็นข้อจำกัดสำหรับคุณ

**คุณไม่ได้ถือ credential ของเขา** คุณได้คำตอบของคำถามที่คุณถาม ไม่ใช่สำเนา
ของเอกสาร

**คุณทำสิ่งที่ไม่ได้ประกาศไว้ไม่ได้** capability ถูกตรวจก่อนโค้ดคุณจะรัน และ
capability ที่ประกาศแล้วไม่ได้ใช้คือ build ที่ล้มเหลว — การขอสิ่งที่ไม่ได้ใช้
คือวิธีที่ทำให้การให้ความยินยอมหมดความหมาย

**บางอย่างไม่มีในภาษานี้เลย** ไม่มี floating point ไม่มี loop ไม่มี recursion
ไม่มีวิธีประกอบ string แต่ละข้อมีเหตุผล และเหตุผลอยู่ใน
[ข้อกำหนดภาษา](../spec.md) ถ้าคุณอยากอ่าน ส่วนคำอธิบายเชิงปฏิบัติคือ
Micro App เป็นของเล็กและแม่นยำ และภาษานี้จะไม่ยอมให้คุณทำให้มันใหญ่และคลุมเครือ

## Micro App มีสองแบบ

คุณเขียนเป็น webview ก็ได้: HTML และ JavaScript ของคุณเอง อยู่ในเฟรม
คุยกับ wallet ผ่าน bridge บางๆ

มันเป็นทางเลือกจริงจัง และเป็นทางที่เร็วกว่าถ้าจะดึงทีมเว็บที่มีอยู่แล้วเข้ามา
สิ่งที่มันทำไม่ได้คืออะไรก็ตามที่ความปลอดภัยขึ้นอยู่กับการที่ host รู้ว่ามีอะไรรันไป
— เพราะ webview รันโค้ดที่ host ไม่ได้คอมไพล์ และวาดหน้าจอที่ host ไม่ได้วาด

| | webview | VAL |
| --- | --- | --- |
| วาดหน้าจอเอง | ได้ | ไม่ได้ |
| อ่าน credential ผ่านชีตของ host | ได้ | ได้ |
| ออก credential | ไม่ได้ | ได้ |
| รับชำระเงิน | ไม่ได้ | ได้ |
| เซ็นสิ่งที่ผู้ใช้อนุมัติ | ไม่ได้ | ได้ |

นี่ไม่ใช่นโยบายที่เราเลือกมากดดันคุณ มันเป็นผลที่ตามมา: host พูดไม่ได้ว่า
webview ของคุณทำอะไรลงไป มันจึงเสนอ capability ที่ต้องอาศัยการพูดแบบนั้นให้คุณ
ไม่ได้ ถ้าคุณต้องการ capability เหล่านั้น คุณต้องใช้ VAL

## Micro App ประกอบด้วยอะไร

package หนึ่งชุด — หนึ่งไดเรกทอรี หลายไฟล์ หนึ่งตัวตน:

```
loyalty.val      ตัวแอป: capability, credential, action
wallet.val       หน้าจอหนึ่งหน้า อยู่ใน package เดียวกัน
text.json        ทุกประโยคที่ผู้ใช้จะได้อ่าน ในทุกภาษา
```

คุณคอมไพล์ เซ็น แล้วส่งมอบไฟล์ `.va` host ตรวจทั้งหมดใหม่ตั้งแต่ต้น เพราะการที่
build ของคุณผ่านไม่ได้พิสูจน์อะไรเกี่ยวกับ package ของคุณเลย — มันเป็น build
ของคุณเอง
