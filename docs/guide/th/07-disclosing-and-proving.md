# การเปิดเผยและการพิสูจน์

```val
execute {
  present {
    disclose checked.claims.country
    prove checked.claims.birthdate <= context.time.now - duration(years: 20)
  }
}
```

**`disclose` ยื่นค่าให้** เขาได้รู้ประเทศ

**`prove` ยื่นคำตอบให้** เขาได้รู้ว่าคนคนหนึ่งอายุเกินยี่สิบ เขาไม่ได้รู้วันเกิด
และคำนวณย้อนกลับทีหลังไม่ได้

## prove ไม่ใช่การเปรียบเทียบที่คุณทำเอง

การอ่านวันเกิดแล้วเปรียบเทียบคือการเปิดเผยที่ตามด้วยการเปรียบเทียบ คุณเห็นวันที่
นั้นแล้ว และผู้ดูแลประตูก็ได้แต่เชื่อใจว่าคุณจะไม่เก็บมันไว้

`prove` ผลิต `Proof<bool>` และไม่มีอะไรที่อ่อนกว่านั้น ในที่ที่ wallet ผลิต
zero-knowledge proof จริงๆ ไม่ได้ **แอปของคุณ build ไม่ผ่าน** มันไม่เคยถอยไป
เปิดเผยแล้วเปรียบเทียบแทน

## ทั้งคู่เป็น effect

การเปิดเผยต้องใช้ `disclosure.present` ปรากฏใน `execute` พร้อมกับอย่างอื่น และ
ลงไปอยู่ใน execution record

**หนึ่งการเปิดเผยต่อหนึ่ง action** effect ใน `execute` เป็นชุดเดียว และการเปิดเผย
ย้อนกลับไม่ได้ — ครั้งที่สองจึงขึ้นกับชุดที่ครั้งแรกทำเสร็จไปแล้วไม่ได้
สองการเปิดเผยต้องการความยินยอมสองครั้ง ซึ่งก็คือสอง action

## อะไรที่พิสูจน์ได้

`prove` คอมไพล์ลงไปเป็นวงจร และมีแค่ส่วนหนึ่งของภาษาที่ทำได้ คอมไพเลอร์บอกคุณ
ตอนที่คุณออกนอกส่วนนั้น

**ภายใน:** จำนวนเต็มที่ประกาศความกว้าง วันและเวลาที่เทียบกันแบบจำนวนเต็ม
การเท่ากันของ string `switch` และ `?:` และ list combinator ที่รู้ความยาวตอน
คอมไพล์ — ซึ่งเป็นสิ่งที่ `limit` ในการประกาศ `data` มีไว้เพื่อการนั้น

สองเรื่องที่ควรรู้ก่อนเขียน:

- **ทุกกิ่งมีราคา** วงจรจ่ายให้ทั้งสองข้างของเงื่อนไข `?:` ที่ดูราคาถูกคือการ
  คำนวณสองชุด
- **มันจ่ายตามขอบเขต ไม่ใช่ตามข้อมูล** proof เหนือ list ที่ยาวไม่เกิน 200
  จ่ายค่าบวก 200 ครั้ง ไม่ว่าผู้ใช้จะถือสองรายการหรือสองร้อยรายการ ซึ่งก็เป็น
  เหตุผลที่มันไม่รั่วว่าเขาถืออยู่กี่รายการ

## การพิสูจน์เหนือ state ของคุณเอง

state เป็น Merkle tree ฟิลด์เดียวจึงแสดงได้โดยไม่ต้องเปิดที่เหลือ

```val
disclose state.member.tier
prove state.lifetimePoints >= 10_000
```

ให้รู้ว่าคุณกำลังอ้างอะไร claim ใน credential มีผู้ออกที่เซ็นมันหนุนหลัง ส่วน
ฟิลด์ใน state มีห่วงโซ่ของ record ที่ผลิตมันหนุนหลัง: ถูกต้องตามกติกาที่ใครก็
รันซ้ำได้ แต่ไม่มีบุคคลที่สามอยู่เบื้องหลังข้อมูลนำเข้า ผู้ตรวจสอบถูกบอกว่ากำลังดู
อันไหนในสองอันนั้น

## อะไรที่พิสูจน์ไม่ได้

อะไรก็ตามที่มาจาก API คำตอบของ query เป็นคำพูดของใครคนหนึ่ง ไม่ใช่ลายเซ็นของใคร
คอมไพเลอร์ปฏิเสธมัน และทางเลือกที่ซื่อสัตย์คือเปิดเผยตัวเลขนั้นแล้วบอกว่ามันมา
จากไหน
