# การเผยแพร่

```bash
valpack build ./my-app -o my-app.va
valpack verify my-app.va
```

`.va` คือเอกสารที่ถูกเซ็นหนึ่งฉบับ: source ของคุณ manifest text bundle รายงาน
capability ที่อนุมานมา แฮชต่อไฟล์ และลายเซ็นครอบทั้งหมดนั้น

## source อยู่ใน package

ไม่ใช่ source *หรือ* ผลลัพธ์ที่คอมไพล์แล้ว — เป็น source เสมอ แฮชของสิ่งที่
คอมไพล์แล้วพิสูจน์ว่ามันคือสิ่งที่ใครบางคนเซ็น แต่ไม่เคยพิสูจน์ว่ามันคือโปรแกรมที่
ใครบางคนอ่าน

นี่คือสิ่งที่ทำให้ host ตรวจ package ของคุณได้ตั้งแต่หลักการแรกแทนที่จะเชื่อ build
ของคุณ และมันต่อรองไม่ได้: ทุกอย่างที่เหลือที่นี่ตั้งอยู่บนมัน

## host ทำอะไรบ้างก่อนรับคุณเข้าไป

ห้าอย่าง และแต่ละอย่างคือสิ่งที่ไม่อย่างนั้นคุณจะถูกเชื่อใจแทน

1. **ทุก source แฮชออกมาตรงกับที่ integrity บอก** ไม่มีอะไรถูกแก้หลังเซ็น
2. **ลายเซ็นครอบไบต์ชุดนี้** โดยกุญแจที่ manifest ของคุณระบุชื่อ
3. **มันคอมไพล์ผ่าน** — ตรวจที่นั่น ไม่ใช่รับมาจาก build ที่ไม่มีใครอื่นเคยรัน
4. **รายงานที่มันส่งมาคือรายงานที่โค้ดของมันผลิต** ข้อนี้คือข้อที่สำคัญ
   การแก้รายงานทำให้ลายเซ็นพัง แต่คู่ต่อสู้ที่น่าสนใจไม่ใช่คนแปลกหน้าระหว่างทาง:
   มันคือผู้เผยแพร่ที่เซ็นรายงานที่พูดถึงแอปตัวเองน้อยกว่าความจริง ลายเซ็นจับ
   เรื่องนั้นไม่ได้ การคำนวณใหม่จับได้
5. **ทุกภาษาที่ manifest ของคุณสัญญาไว้มีครบทุก key** ภาษาของตลาดหนึ่งขาดไป
   คือ build ที่ล้มเหลว

จากนั้นเป็น policy ของ host เอง: แอปชนิดของคุณถือ capability ที่คุณประกาศได้ไหม
และมันเรนเดอร์แคตตาล็อกที่คุณ build ไว้ได้หรือเปล่า

## ทำซ้ำได้

input ชุดเดิมผลิตไบต์ชุดเดิม สองคนจึงตรวจได้ว่าถืออยู่คือแอปเดียวกันโดยไม่ต้อง
ถามกันและกัน

## ใครเซ็น credential ที่คุณออก

ไม่ใช่แอปของคุณ มันไม่มีกุญแจผู้ออกและต้องไม่มี

```
เครื่องผู้ใช้    รัน action แล้วเซ็น execution record
   ↓
backend ของคุณ  ตรวจ record นั้น แล้วเซ็น credential ด้วยกุญแจผู้ออกของคุณ
   ↓
เครื่องผู้ใช้    เก็บ credential ไว้
```

นี่คือเหตุผลว่าทำไมผู้เผยแพร่ต้องมีเซิร์ฟเวอร์เลย และนี่คือทั้งหมดที่เซิร์ฟเวอร์ทำ:
มันไม่ได้รัน VAL ไม่ได้ถือ state และไม่เคยเห็น state มันตรวจลายเซ็น แปลงแฮชของ
โค้ดกลับไปเป็นเวอร์ชันที่คุณเผยแพร่ ตรวจห่วงโซ่ความเชื่อถือ ตรวจ proof ถ้ามี —
กุญแจสำหรับตรวจมาจากวงจรที่คอมไพล์แล้ว มันจึงรู้เองว่า predicate ไหนถูกพิสูจน์
แทนที่จะถูกบอก — แล้วก็เซ็น หรือปฏิเสธ

**การปฏิเสธคือประเด็น** คนที่ถือเครื่องอยู่เขียน state ของตัวเองใหม่ได้ แต่เขา
ทำให้คุณเซ็น credential ให้กับการรันที่ตรวจไม่ผ่านไม่ได้

## เวอร์ชัน

`version` อยู่บรรทัดแรกและไม่ใช่ของประดับ เวอร์ชันใหม่คือความยินยอมครั้งใหม่
เมื่อใดก็ตามที่รายงาน capability ต่างไป `kind` เปลี่ยน หรือรูปร่างของ `state`
เปลี่ยน

ข้อสุดท้ายพา state ไปด้วย วางแผนเผื่อไว้: สิ่งที่สำคัญควรอยู่ใน credential
ไม่ใช่ใน `state`
