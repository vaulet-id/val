# การเผยแพร่

```bash
valpack build ./my-app -o my-app.vapp
valpack verify my-app.vapp
```

`.vapp` คือเอกสารที่ถูกเซ็นหนึ่งฉบับ: **module ที่คอมไพล์แล้ว** manifest
text bundle รายงาน capability แฮช integrity และลายเซ็นครอบทั้งหมด source ชุดเดิม
ผลิตไบต์ชุดเดิม สองคนจึงตรวจได้ว่าถืออยู่คือแอปเดียวกัน

## source ไม่ได้อยู่ใน package

**คุณคอมไพล์ wallet ไม่เคยคอมไพล์** โทรศัพท์ที่มีคอมไพเลอร์อยู่ข้างในคือโทรศัพท์
ที่ต้องรับโปรแกรมเข้ามา และสิ่งที่มันรันหลังจากนั้นคือสิ่งที่ไม่มีใครนอก build
ของคุณเคยเห็น สิ่งที่ส่งจึงเป็น module และ wallet ตรวจกับ *สิ่งนั้น* — ตัวที่
มันจะรันจริง

นี่ไม่ใช่จุดยืนที่อ่อนกว่าอย่างที่ฟังดู รายงานไม่ได้อ่านมาจาก manifest ของคุณ
มัน **วัดมาจาก import section ของ module เอง** ซึ่งคือรายการของสิ่งที่โค้ดเรียกได้
module เรียกสิ่งที่มัน import และไม่มีอย่างอื่น รายงานที่บอกน้อยกว่าความจริงจึง
ไม่ใช่คำโกหกที่ผู้เผยแพร่พูดได้ — มันคือ module ที่จะ trap ทันทีที่เอื้อมไปหาสิ่ง
ที่ไม่ได้ประกาศ

source มีไว้เพื่อ `valpack reproduce`: ใครก็ตามที่มี source ที่คุณเผยแพร่ build
แล้วเทียบไบต์ นั่นผูก module เข้ากับ source *นอก* wallet ซึ่งเป็นที่ที่การตรวจ
ที่ต้องใช้คอมไพเลอร์ควรอยู่

## wallet ตรวจอะไรก่อนรับคุณเข้าไป

1. **module แฮชออกมาตรงกับที่ integrity บอก** ไม่มีอะไรถูกแก้หลังเซ็น
2. **ลายเซ็นครอบไบต์ชุดนี้** โดยกุญแจที่ manifest ของคุณระบุชื่อ — และถ้าเป็น
   `did:web` กุญแจนั้นต้องเป็นกุญแจที่ชื่อนั้นเผยแพร่เอง
3. **รายงานคือรายงานที่ module วัดออกมาได้** ไม่ใช่อันที่คุณเขียนไว้: มันถูก
   คำนวณใหม่จาก import แล้วเทียบ
4. **มันไม่ import สิ่งที่ host นี้ไม่มีให้** import ที่ไม่รู้จักถูกปฏิเสธตอน
   install ไม่ใช่ตอนที่กดปุ่มที่จะไปเอื้อมถึงมัน
5. **ทุกภาษาที่ manifest ของคุณสัญญาไว้มีครบทุก key**

จากนั้นเป็น policy ของ wallet เอง: แอปชนิดของคุณถือ capability ที่คุณประกาศได้ไหม
และมันเรนเดอร์แคตตาล็อกที่คุณ build ไว้ได้หรือเปล่า

## ใครเซ็น credential ที่คุณออก

ไม่ใช่แอปของคุณ มันไม่มีกุญแจผู้ออกและต้องไม่มี

```
เครื่องผู้ใช้    รัน action แล้วเซ็น execution record
   ↓
backend ของคุณ  ตรวจ record นั้น แล้วเซ็น credential ด้วยกุญแจผู้ออกของคุณ
   ↓
เครื่องผู้ใช้    เก็บ credential ไว้
```

นี่คือเหตุผลว่าทำไมผู้เผยแพร่ต้องมีเซิร์ฟเวอร์เลย และนี่คือทั้งหมดที่เซิร์ฟเวอร์ทำ
มันไม่ได้รัน VAL ไม่ได้ถือ state และไม่เห็นมัน มันตรวจลายเซ็น แปลงแฮชของโค้ด
กลับไปเป็นเวอร์ชันที่คุณเผยแพร่ ตรวจห่วงโซ่ความเชื่อถือ ตรวจ proof ถ้ามี —
กุญแจสำหรับตรวจมาจากวงจรที่คอมไพล์แล้ว มันจึงรู้เองว่า predicate ไหนถูกพิสูจน์ —
แล้วจึงเซ็นหรือปฏิเสธ

คนที่ถือเครื่องอยู่เขียน state ของตัวเองใหม่ได้ แต่เขาทำให้เซิร์ฟเวอร์ของคุณเซ็น
credential ให้กับการรันที่ตรวจไม่ผ่านไม่ได้

## เวอร์ชัน

`version` อยู่บรรทัดแรกและไม่ใช่ของประดับ เวอร์ชันใหม่คือความยินยอมครั้งใหม่
เมื่อใดก็ตามที่รายงาน capability ต่างไป ชนิดของแอปเปลี่ยน หรือรูปร่างของ `state`
เปลี่ยน

ข้อสุดท้ายพา state ไปด้วย วางแผนเผื่อไว้: สิ่งที่สำคัญควรอยู่ใน credential
ไม่ใช่ใน `state`
