# การเผยแพร่

```bash
valpack build ./my-app -o my-app.va
valpack verify my-app.va
```

`.va` คือเอกสารที่ถูกเซ็นหนึ่งฉบับ: source ของคุณ manifest text bundle รายงาน
capability ที่อนุมานมา แฮชต่อไฟล์ และลายเซ็นครอบทั้งหมด input ชุดเดิมผลิตไบต์
ชุดเดิม สองคนจึงตรวจได้ว่าถืออยู่คือแอปเดียวกัน

## source อยู่ใน package

ไม่ใช่ source *หรือ* ผลลัพธ์ที่คอมไพล์แล้ว — เป็น source เสมอ แฮชของสิ่งที่
คอมไพล์แล้วพิสูจน์ว่ามันคือสิ่งที่ใครบางคนเซ็น แต่ไม่เคยพิสูจน์ว่ามันคือโปรแกรม
ที่ใครบางคนอ่าน

นี่คือสิ่งที่ทำให้ wallet ตรวจ package ของคุณได้จากหลักการแรกแทนที่จะเชื่อ build
ของคุณ

## wallet ตรวจอะไรก่อนรับคุณเข้าไป

1. **ทุก source แฮชออกมาตรงกับที่ integrity บอก** ไม่มีอะไรถูกแก้หลังเซ็น
2. **ลายเซ็นครอบไบต์ชุดนี้** โดยกุญแจที่ manifest ของคุณระบุชื่อ
3. **มันคอมไพล์ผ่าน** — ตรวจที่นั่น ไม่ใช่รับมาจาก build ที่ไม่มีใครอื่นเคยรัน
4. **รายงานที่มันส่งมาคือรายงานที่โค้ดของมันผลิต** การแก้รายงานทำให้ลายเซ็นพัง
   แต่กรณีที่สำคัญคือผู้เผยแพร่ที่เซ็นรายงานซึ่งพูดถึงแอปตัวเองน้อยกว่าความจริง
   การคำนวณใหม่จับเรื่องนั้นได้
5. **ทุกภาษาที่ manifest ของคุณสัญญาไว้มีครบทุก key**

จากนั้นเป็น policy ของ wallet เอง: แอปชนิดของคุณถือ capability ที่คุณประกาศได้ไหม
และมันเรนเดอร์แคตตาล็อกที่คุณ build ไว้ได้หรือเปล่า

## ใครเซ็น credential ที่คุณออก

ไม่ใช่แอปของคุณ มันไม่มีกุญแจผู้ออกและต้องไม่มี

```
เครื่องผู้ใช้    รัน action แล้วเซ็น execution record
   ↓
backend ของคุณ  ตรวจ record นั้น แล้วเซ็น credential ด้วยกุญแจผู้ออกของคุณ
   ↓
เครื่องผู้ใช้    เก็บ credential ไว้
```

นี่คือเหตุผลว่าทำไมผู้เผยแพร่ต้องมีเซิร์ฟเวอร์เลย และนี่คือทั้งหมดที่เซิร์ฟเวอร์ทำ
มันไม่ได้รัน VAL ไม่ได้ถือ state และไม่เห็นมัน มันตรวจลายเซ็น แปลงแฮชของโค้ด
กลับไปเป็นเวอร์ชันที่คุณเผยแพร่ ตรวจห่วงโซ่ความเชื่อถือ ตรวจ proof ถ้ามี —
กุญแจสำหรับตรวจมาจากวงจรที่คอมไพล์แล้ว มันจึงรู้เองว่า predicate ไหนถูกพิสูจน์ —
แล้วจึงเซ็นหรือปฏิเสธ

คนที่ถือเครื่องอยู่เขียน state ของตัวเองใหม่ได้ แต่เขาทำให้เซิร์ฟเวอร์ของคุณเซ็น
credential ให้กับการรันที่ตรวจไม่ผ่านไม่ได้

## เวอร์ชัน

`version` อยู่บรรทัดแรกและไม่ใช่ของประดับ เวอร์ชันใหม่คือความยินยอมครั้งใหม่
เมื่อใดก็ตามที่รายงาน capability ต่างไป ชนิดของแอปเปลี่ยน หรือรูปร่างของ `state`
เปลี่ยน

ข้อสุดท้ายพา state ไปด้วย วางแผนเผื่อไว้: สิ่งที่สำคัญควรอยู่ใน credential
ไม่ใช่ใน `state`
