# Action

action เป็นสิ่งเดียวที่รัน:

```
input → require → verify → compute → update → execute
```

จะละเฟสไหนก็ได้ แต่ห้ามสลับลำดับ

## เลือกวิธีที่ action จะปฏิเสธ

มีสี่ทางที่ action จะไม่ commit และการเลือกผิดคือความผิดพลาดที่พบบ่อยที่สุดใน
แอปตัวแรก

| | ใครเห็น | ใช้เมื่อไหร่ |
| --- | --- | --- |
| `require` ไม่ผ่าน | ไม่มีใคร | สิ่งที่ไม่ควรเป็นเท็จเลย ถ้าเป็นเท็จแปลว่าคุณมีบั๊ก |
| `verify` ไม่ผ่าน | ผู้ใช้ | credential ปลอม หมดอายุ หรืออยู่นอก anchor |
| `refuse "key"` | ผู้ใช้ | กติกาของคุณเอง: น้อยไป เร็วไป หรือรับไปแล้ว |
| wallet ปฏิเสธ | ผู้ใช้ | เขาตอบว่าไม่ |

กติกาทางธุรกิจที่อยู่ใน `require` ให้ผลเป็นการล้มในที่ที่คุณอยากได้ข้อความ
ส่วนบั๊กที่อยู่ใน `refuse` ทำให้ใครสักคนได้อ่านประโยคสุภาพเกี่ยวกับความผิดพลาด
ของคุณ

## ประกาศ action ไว้ ไม่ได้แปลว่ามันจะรัน

action รันเพราะมีคนกดอะไรบางอย่าง ถ้าไม่มีหน้าจอไหนใน package ระบุชื่อมันไว้ใน
`onTap` ก็ไม่มีอะไรไปถึงมันได้ — และคอมไพเลอร์บอกคุณ เพราะ capability ที่มันต้องใช้
ยังอยู่บนใบยินยอม

action อยู่ไฟล์หนึ่งแล้วถูกกดจากหน้าจอในอีกไฟล์ได้ package คือ scope เดียว

## `input`

```val
input {
  receipt: Credential<PurchaseReceipt>
}
```

ชื่อที่ประกาศตรงนี้อยู่ใน scope ของทุกเฟสถัดไปแบบเปลือย — `receipt` ไม่ใช่
`input.receipt`

## `require`

เงื่อนไขก่อนหน้า และการทำให้ optional แคบลง:

```val
require {
  state.member exists
  amount > 0
}
```

ใช้ `exists` ไม่ใช่ `!= null` จนกว่าคุณจะบอก การอ่านทะลุ `state.member` เป็น
type error ไม่ใช่การล้มทีหลัง

## `verify`

trust policy และเป็นที่เดียวที่ credential กลายเป็นของที่ใช้ได้ หลายนิพจน์ถูก
รวมกันด้วย AND

## `compute`

pure ไม่มี effect และไม่มี effect ไหนซ่อนอยู่หลังฟังก์ชันได้ — ทุก `function`
ในภาษานี้เป็น pure

เลขคณิต trap ไม่ใช่ wrap: การล้นและการหารด้วยศูนย์หยุด action

`const` คือนิยาม ส่วน `let` คือตัวแปร:

```val
compute {
  let label = "bronze"
  if (points >= 1000) {
    label = "gold"
  }
  const fee = amount > 100_000 ? 0 : 20
}
```

ชื่อที่เขียนซ้ำได้ เขียนได้เฉพาะใน `compute` กับในฟังก์ชัน — เฟสอื่นไม่ใช่ที่ที่ค่าถูกคิดออกมา
ส่วน `state` ไม่เคยถูกกำหนดค่า มันเปลี่ยนใน `update` และทุกการเปลี่ยนแปลงเป็นบรรทัดใน record

ถ้าอ่านแล้วเหมือนกัน ใช้ `const` ก่อน บล็อกของนิยามอ่านจากตรงไหนก็ได้
ส่วนบล็อกของตัวแปรต้องอ่านเรียงทางเดียว

หมายเหตุ: ลำดับ effect ที่ใช้ร่วมกันสาม action ต้องเขียนออกมาสามครั้ง แลกกับการที่
ทุกอย่างที่ action ทำได้อยู่ในบล็อก `execute` ของมัน

## `update`

เป็น patch ไม่ใช่นิพจน์:

```val
update {
  lifetimePoints: total
  member.points:  state.member.points + earned
  member.tier:    tier
}
```

แต่ละบรรทัดระบุฟิลด์และค่าที่มันจะเป็น อะไรที่ไม่ถูกระบุก็ไม่เปลี่ยน path ซ้อนกัน
ได้แต่มี index ของ list ไม่ได้ — ให้สร้าง list ใหม่ใน `compute` แล้วมาระบุชื่อ
ที่นี่ในบรรทัดเดียว

ทุกบรรทัดอ่าน state ที่ action เริ่มต้นมา `a: state.b` คู่กับ `b: state.a` คือการสลับค่า
ถ้าอ่านเป็นการกำหนดค่าทีละบรรทัด มันจะกลายเป็นการทับค่าหนึ่งด้วยอีกค่าหนึ่ง

## `execute`

ที่เดียวที่ effect ปรากฏ และมันไม่ได้ลงมือทำ:

```val
execute {
  credential.issue(LoyaltyMember { points: next.member.points })
}
```

`next` คือ state ที่ `update` ผลิตออกมา ใช้มันแทนที่จะคำนวณเลขเดิมซ้ำตรงนี้

**effect เป็นชุดเดียว** wallet เอาไปทั้งหมดหรือไม่เอาเลย และ state ของคุณ commit
ก็ต่อเมื่อมันเอาไป ไม่มี effect ไหนอ่านผลของอีกอันได้ — ถ้าอันหนึ่งขึ้นกับผลของ
อีกอัน นั่นคือสอง action

**เปิดเผยได้อย่างมากหนึ่งครั้งต่อหนึ่ง action** การเปิดเผยย้อนกลับไม่ได้
ครั้งที่สองจึงขึ้นกับชุดที่ครั้งแรกทำเสร็จไปแล้วไม่ได้

effect ที่ย้อนกลับไม่ได้ถูกจัดไว้ท้ายสุดโดยอัตโนมัติ
